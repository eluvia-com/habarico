Renders an array of scalar values as a row of chips, or as plain labels stacked one per line.

It is the fallback for arrays: when the items are objects or references, the dispatcher picks
[SchemaObjectArrayField](./object-array-field.mdx) or
[SchemaReferenceArrayField](./reference-array-field.mdx) instead.

## Example

```tsx
<ChipArrayField source="tags" />

// with an enum the raw values resolve to their label, colour and icon
<ChipArrayField source="channels" choices={channelChoices} iconsKey="channels" />
```

## Props

On top of these it accepts the shared [field props](./index.md#common-props).

| Name                | Type      | Default | Description                                                                                            |
| ------------------- | --------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `source` (required) | `string`  | —       | Name of the array field on the record                                                                  |
| `choices`           | `Choices` | —       | Enum of the **items** (`{value, label, color?, icon?}`); without it the raw values are shown           |
| `iconsKey`          | `string`  | —       | Key into the `iconsMap` on [SchemaAdmin](../base-components/schema-admin.md), giving each chip an icon |
| `variant`           | `'chip' \| 'text'` | `fieldDefaults.choices` | Chips, or plain labels one per line — see below                              |

It is the presence of `choices` — not a `format` flag — that switches on the enum branch. Inside a
datagrid, chips that have an icon collapse to icon-only, tooltipped glyphs; chips without one stay
as chips, ellipsized to the column width.

Chips never link anywhere — `linkType` is `false`. For clickable references use
[SchemaReferenceField](./reference-field.mdx).

`defaultFieldProvider` fills both props from the item schema: `choices` from `items.enum` and
`iconsKey` from `items.options.choices.iconsKey`.

## `variant`

`'text'` renders the label as plain text instead of a chip — but **only for an enum whose options
define no color of their own**. A chip of a colored option *carries* the color, and plain text
cannot, so a colored enum keeps its chips under `'text'` as well. The test is run over the whole
option list, not per value, so one field never mixes chips and bare words down a column; a `color`
of `'inherit'` counts as no color.

```tsx
<ChipArrayField source="channels" choices={channelChoices} variant="text" />
```

Left unset, `variant` follows
[`fieldDefaults.choices`](../base-components/field-defaults.md) — the same key the other choices
field reads, so a single choice and an array of them are never rendered in two different shapes.
`'chip'` is the default behind that.

The text shape stacks the labels one per line, for the same reason
[SchemaReferenceArrayField](./reference-array-field.mdx) stacks its links: a row of bare words reads
as one run-on phrase, where chips carry a shape that keeps neighbours apart. Raw values with no enum
behind them have no color to lose and always honour `'text'`.

## How an array is dispatched

`defaultFieldProvider` looks at `schema.items`, not at the array itself:

| `items`                          | Component                                                |
| -------------------------------- | -------------------------------------------------------- |
| `type: 'object'`, outside a list | [SchemaObjectArrayField](./object-array-field.mdx)       |
| `type: 'object'`, inside a list  | Nothing — object arrays are not rendered as a column     |
| carries a `reference`            | [SchemaReferenceArrayField](./reference-array-field.mdx) |
| anything else                    | `ChipArrayField`                                         |

An array without `items` in its schema renders nothing at all.

## Schema mapping

```json
{
  "name": "tags",
  "type": "array",
  "items": {
    "type": "string",
    "format": "choices",
    "enum": [{ "value": "sale", "label": "Sale", "color": "success" }]
  }
}
```
