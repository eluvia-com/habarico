## Install NPM packages

For local development: Set your `GITLAB_TOKEN` environment variable. For example in your `~/.bashrc` or `~/.profile` file.
There should be set your personal Gitlab token:

```bash
export GITLAB_TOKEN=your_personal_token
```

To install all dependencies, run the following command:

```bash
pnpm install
```

## Router requirement

This library uses `useBlocker` from React Router to guard against accidental navigation away from forms with unsaved changes. This feature requires a **data router** (`createBrowserRouter` or `createHashRouter`) — it does not work with the legacy `<BrowserRouter>` component.

**Recommended setup** — let React Admin manage the router internally (do not wrap `SchemaAdmin` in your own router):

```tsx
// ✅ Correct — React Admin creates a data router internally
<SchemaAdmin ... />
```

If your app needs to control the router (e.g. for `basename`), use `createBrowserRouter`:

```tsx
// ✅ Also correct — explicit data router
import {createBrowserRouter, RouterProvider} from 'react-router-dom';

const router = createBrowserRouter([{path: '*', element: <SchemaAdmin ... />}]);

<RouterProvider router={router} />
```

```tsx
// ❌ Avoid — legacy router, unsaved-changes guard will be silently disabled
<BrowserRouter>
  <SchemaAdmin ... />
</BrowserRouter>
```

## Usage in the project

Pick the source you consume the library from — the published package for normal
project work, a local checkout when you develop the library and the project side by side.

<Tabs groupId="habarico-source">
<TabItem value="registry" label="NPM package registry" default>

```bash
pnpm add @eluvia/habarico
```

Every framework dependency is a **peer** dependency — the library bundles none of them, so install
them in the project yourself, in a version that satisfies the range:

| Peer | Range |
|---|---|
| `react` / `react-dom` | `^18.0.0 \|\| ^19.0.0` |
| `react-admin`, `ra-core`, `ra-ui-materialui`, `ra-i18n-polyglot` | `~5.14.5` |
| `react-router` / `react-router-dom` | `^6.0.0 \|\| ^7.0.0` |
| `react-hook-form` | `^7.72.0` |
| `@mui/material`, `@mui/icons-material` | `^7.0.0` |
| `@mui/x-data-grid`, `@mui/x-charts`, `@mui/x-date-pickers` | `^9.3.0` |
| `@mui/x-tree-view` | `^9.1.0` |
| `@emotion/react`, `@emotion/styled` | `^11.0.0` |
| `@tanstack/react-query` | `^5.0.0` |
| `@eluvia/auth` | `^2.3.1` |

:::caution
The React Admin packages are pinned to a patch range (`~5.14.5`), not a major one. A project on a
different React Admin minor will hit duplicated contexts — two copies of `ra-core` in the bundle
means the store, the identity and the notification system stop being shared.
:::

</TabItem>
<TabItem value="local" label="Local repository">

Run this **in the project**, pointing at your checkouts — the free library first, the paid one
second:

```bash
pydev link-library <path-to-libs>/habarico-base/node <path-to-libs>/habarico-enterprise/node-enterprise
```

`<path-to-libs>` is the directory holding your library checkouts — the same placeholder the Ruby services use in their compose files. Relative or absolute, both work.
Pass only the packages you actually develop; either one works on its own. Paths are resolved from
the project directory and turned into absolute ones.

:::caution
The order matters when you link both. `habarico-enterprise` points its own `@eluvia/habarico` at
the copy the project holds — which is the symlink the first argument creates. Link it first and
both packages share one instance of the library, React and React Admin; link it second and you get
two, which shows up as `Cannot read properties of null (reading 'useMemo')`.
:::

The command generates a `pnpm-workspace.yaml` in each library that points every peer dependency at
the project's copy, then installs. Nothing else is needed — the built `lib/` bundle the project
consumes is already in place.

Then watch for changes in the library you edit:

```bash
pnpm watch
```

Undo it with the matching command, in any order:

```bash
pydev unlink-library <path-to-libs>/habarico-base/node <path-to-libs>/habarico-enterprise/node-enterprise
```

:::tip
If the project's dev server was already running, drop Vite's dependency cache after linking —
`rm -rf node_modules/.vite` — otherwise it serves the pre-bundled copy of the old package.
:::
